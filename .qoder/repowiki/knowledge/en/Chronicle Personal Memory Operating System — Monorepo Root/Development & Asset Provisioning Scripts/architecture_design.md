This is a flat collection of independent utility scripts with no shared library — each file is self-contained and invoked directly from the terminal. They fall into four functional groups:
- Asset downloaders: `curated_download.js`, `ddg_download_all.js`, `ddg_images.js`, `fetch_itunes_posters.js`, `scrape_tmdb.js`, `scrape_unsplash.js`, `wiki_fetch.js` use `fetch()` to pull images from DuckDuckGo, iTunes, TMDB, Unsplash, and Wikipedia.
- PowerShell media grabbers: `download_images.ps1` (Pollinations AI), `download_videos.ps1` and `redownload_videos.ps1` (yt-dlp against YouTube) write files into `public/landing/images` and `public/landing/videos`.
- Transcript restoration / rollback: `restore.cjs` through `restore4.cjs`, `my_restore.cjs`, `final_rollback.cjs`, `rollback_hero_current.cjs`, `rollback_latest.cjs`, `search_all.cjs`, `extract.cjs`, `extract_hero_node.cjs`, `extract_worlds.cjs`, `ps_extract.ps1` all parse `.gemini\antigravity-cli\brain\...\.system_generated\logs\transcript_full.jsonl` to extract `write_to_file` tool calls and rewrite `src/components/landing-v2/*.tsx` files.
- Browser QA: `check_console.js`, `check_errors.js`, `screenshot.js`, `test_opacity.js`, `test_scroll.js`, `test_scroll2.js` drive Playwright Chromium against `http://localhost:5173/new-landing`.
- Infrastructure: `docker-compose.e2e.yml` spins up Postgres, Redis, the backend API, the Bun dev server, and a Playwright E2E container.
Dependency direction is one-way: scripts depend on external APIs (DuckDuckGo, iTunes, TMDB, Unsplash, Wikipedia, Pollinations, YouTube via yt-dlp) and on the local filesystem; they never import each other.
