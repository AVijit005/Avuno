Each `.tsx` file is a TanStack Router route declared via `createFileRoute`, mapping directly to a URL under `/app/library/`. The index route (`app.library.index.tsx`) is the dashboard hub: it composes multiple data hooks (`useLibrary`, `useLibraryByStatus`, `useLibraryStats`, `useCollections`, `useChallenges`) and renders editorial sections through shared components (`SectionHeader`, `RevealSection`, `PullQuote`, `Collage`). A dynamic route `app.library.$kind.tsx` validates the kind against a local `KINDS` set and throws `notFound()` for invalid types. Dedicated status routes (`continue`, `planning`, `favorites`, `completed`, `paused`, `dropped`, `archived`, `in-progress`, `rewatching`, `recently-finished`) are thin presentational layers that call domain helpers from `@/lib/library` (e.g. `continueJourney()`, `planning()`, `favorites()`) and render them inside a shared `StatusPageShell` component. The `all` route is the only one with client-side filtering/sorting, using `useState` + `useMemo` over items fetched via `useLibrary({ limit: 100 })` or falling back to `snapshotAllItems()` from the local store. Data adapters (`adaptLibraryItem`, `adaptCollectionResponse`) normalize API responses before rendering.
